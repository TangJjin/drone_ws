# 空地协同双环靶标视觉交付说明

## 1. 交付范围

本交付实现 D435i RGB-D 输入下的双环十字靶标定位、中心深度采样、相机坐标反投影，以及面向控制端的视觉伺服接口约定。运行节点为 `air_ground_servo_node`，配置文件为 `config/air_ground_servo.yaml`。

本版本不包含飞控控制消息、YOLO、霍夫圆检测、卡尔曼预测、光流跟踪、落地控制或内外环固定尺寸比例约束。

## 2. 输入、处理和输出

```text
/camera/camera/rgbd
  RGB + aligned depth + RGB CameraInfo
             |
             v
Canny + HoughLinesP 找水平/竖直十字交点
             |
             v
以交点为中心的极坐标边缘覆盖率验证两条环带
             |
             v
10 x 10 深度窗口中位数 + CameraInfo 反投影
             |
             v
/vision/servo/target (VisionServoTarget)
```

| 项目 | 内容 |
| --- | --- |
| RGB-D 输入话题 | `/camera/camera/rgbd` |
| 输入消息 | `realsense2_camera_msgs/msg/RGBD` |
| 控制端订阅话题 | `/vision/servo/target` |
| 输出消息 | `drone_msgs/msg/VisionServoTarget` |
| 控制端使用字段 | `valid`、`confirmed`、`error_x`、`error_y` |
| `error_x/error_y` 单位 | 米，基于 `camera_color_optical_frame` 的横向误差 |
| 默认图像流 | 640 x 480 @ 30 FPS |

`error_x` 为相机光轴到靶标中心的横向米制误差，画面右侧为正；`error_y` 为纵向米制误差，画面下侧为正。它们由检测中心像素和深度反投影得到，不是像素值，也不是 `[-1, 1]` 归一化值：

```text
error_x = (u - cx) / fx * Z
error_y = (v - cy) / fy * Z
```

其中 `(u, v)` 是靶标中心像素，`fx/fy/cx/cy` 来自 RGB CameraInfo，`Z` 是中心深度窗口的中位数。

## 3. 有效坐标判定

节点不会将无效目标作为有效控制测量。`valid=true` 仅在下面所有条件成立时给出：

1. RGB、对齐深度和 RGB CameraInfo 尺寸一致，且 RGB 为 640 x 480。
2. Canny 与 HoughLinesP 找到满足夹角条件的近水平线和近垂直线交点。
3. 围绕该交点的极坐标边缘统计找到两条分开的环带；不要求外环/内环固定为 50 cm/30 cm。
4. 当前中心相对上一帧已接受中心的跳变不超过半幅图像，即 `abs(dx) <= 320 px` 且 `abs(dy) <= 240 px`。
5. 交点处 10 x 10 深度窗口中存在范围内的有效深度，默认范围为 0.1 m 到 10.0 m，并以有效样本的中位数作为深度值。
6. `CameraInfo` 包含有效焦距和主点，可完成像素反投影。

任一条件失败时，视觉端应发布 `valid=false`。控制端应在一段时间内没有收到新消息时进入失目标保护或悬停，不能无限复用旧误差。

## 4. 关键实现说明

### 4.1 双环十字识别

识别主路径位于 `src/air_ground_target_geometry.cpp`：

1. 对 RGB 灰度图执行 Canny。
2. 用 `HoughLinesP` 提取线段，筛选接近水平和接近垂直的线段组合。
3. 将线段交点作为候选中心。
4. 对每个候选中心按角度扫描边缘，在不同半径上统计角度覆盖率。
5. 两个相距足够远、覆盖率足够高的半径同时成立时，判定为双环十字靶标。

这套方法以十字交点为中心，再验证双环，允许局部环边缺失；它不是完整圆拟合，也不使用霍夫圆。

### 4.2 深度与 XYZ

深度图由 D435i 驱动通过 `align_depth.enable: true` 对齐到 RGB 像素坐标。节点在检测中心取 10 x 10 区域，排除 0、非有限值和范围外深度后计算中位数。

使用 RGB CameraInfo 中的 `fx`、`fy`、`cx`、`cy` 反投影：

```text
X = (u - cx) / fx * Z
Y = (v - cy) / fy * Z
Z = depth_m
```

其中 `(u, v)` 是检测到的靶标中心像素坐标，`Z` 是深度窗口中位数。CameraInfo 是 D435i 出厂标定参数，不需要手工重复标定；但更换相机、改变分辨率或裁剪图像时必须重新确认其与输入图像匹配。

### 4.3 调试界面

默认 `view_mode: RGB`，避免调试界面额外执行 Otsu、轮廓提取和轮廓绘制。窗口显示：

- 实际接收 FPS 和目标 FPS；
- OpenCV 实际内部线程数，默认限制为 2；
- 当前图像分辨率、RGB-D 尺寸状态和 CameraInfo 状态；
- 识别中心、相对图像中心的像素误差；
- 深度中位数、有效深度样本数；
- XYZ、双环状态与环半径；
- 黄线：图像中心到检测中心的连线；
- 洋红色点：历史有效中心轨迹；
- 青色十字：图像中心；绿色或红色十字：靶标中心及有效性。

按 `Esc` 或 `q` 退出节点。

## 5. 配置和启动

配置文件的每个参数均有中文注释。默认配置固定选择序列号为 `327122074056` 的 D435i，避免 USB 枚举端口改变造成选错相机。

相机驱动和视觉节点必须分别在两个终端启动，互不拉起或关闭对方。D435i 使用官方 `realsense2_camera` launch；参数与 `air_ground_servo.yaml` 的 `realsense` 分区保持一致。

终端一，启动固定序列号 D435i 驱动：

```bash
cd ~/drone_ws
source /opt/ros/humble/setup.bash
ros2 launch realsense2_camera rs_launch.py \
  camera_namespace:=camera \
  camera_name:=camera \
  serial_no:=_327122074056 \
  enable_color:=true \
  rgb_camera.color_profile:=640x480x30 \
  rgb_camera.power_line_frequency:=1 \
  enable_depth:=true \
  depth_module.depth_profile:=640x480x30 \
  enable_sync:=true \
  enable_rgbd:=true \
  align_depth.enable:=true
```

终端二，确认终端一已出现 `/camera/camera/rgbd` 后启动视觉节点。视觉节点在启动前通过 `taskset -c 6,7` 绑定 CPU 6、7：

```bash
cd ~/drone_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch drone_perception air_ground_servo.launch.py
```

若要临时关闭视觉节点绑核：

```bash
ros2 launch drone_perception air_ground_servo.launch.py cpu_set:=''
```

视觉节点也可在相机驱动已启动时直接运行：

```bash
taskset -c 6,7 ros2 run drone_perception air_ground_servo_node \
  --ros-args -p rgbd_topic:=/camera/camera/rgbd
```

## 6. 验收步骤

1. 编译：`colcon build --packages-select drone_perception --cmake-args -DCMAKE_BUILD_TYPE=Release`。
2. 启动节点后执行 `ros2 topic hz /camera/camera/rgbd`，输入频率应接近 30 Hz。
3. 用 `ros2 topic echo /vision/servo/target` 观察控制接口。靶标被可靠识别时，应持续得到 `valid: true` 及米制 `error_x/error_y`。
4. 将靶标置于相机正前方，观察 HUD：中心误差应接近 `(0, 0)`，`z` 与实际相机到靶标距离接近。
5. 遮挡十字、遮挡其中一个环、制造深度空洞或快速将靶标跳到画面另一侧时，输出应停止，不应出现虚构零坐标。
6. 将靶标静止 60 秒，记录 `/vision/servo/target` 的 `error_x/error_y` 均值、标准差和峰峰值，以此评估进入闭环控制前的稳定性。

## 7. 现场调参边界

当前代码的单元测试覆盖了合成图中的双环十字识别、无双环拒绝、平行线拒绝、空图拒绝、固定 D435i 序列号和 CPU 绑核参数。它们不等价于真实靶标验收。

此前新版节点现场采集 65 秒未发布有效点，说明当前双环门限尚未与真实画面完成匹配。优先在 `air_ground_servo.yaml` 调整以下参数，不要恢复固定 50/30 比例或改回霍夫圆：

| 参数 | 当前值 | 首次建议范围 | 作用 |
| --- | ---: | ---: | --- |
| `min_ring_coverage_ratio` | 0.30 | 0.15 - 0.20 | 允许局部环边缺失，过低会增加误检。 |
| `hough_threshold` | 35 | 25 - 35 | 降低后更容易找到十字线，也更易引入干扰。 |
| `hough_min_line_length` | 45 | 30 - 45 px | 环或十字局部断裂时可适当降低。 |
| `canny_low_threshold` / `canny_high_threshold` | 50 / 150 | 按曝光现场调整 | 需要保证环边和十字边稳定可见。 |

每次只改一组参数，在同一高度、同一曝光条件下重启并记录有效发布率。达到连续稳定输出后，再进行 60 秒静态误差测试和控制端闭环小增益验证。

## 8. 控制端接口约定

控制端只订阅 `/vision/servo/target`，消息类型为 `drone_msgs/msg/VisionServoTarget`，只读取下列四个字段：

| 字段 | 视觉端定义 | 控制端使用方式 |
| --- | --- | --- |
| `valid` | 双环十字、跳变过滤、深度和 CameraInfo 全部通过时为 `true`。 | 必须为 `true` 才允许使用误差控制。 |
| `confirmed` | 单帧确认标志；本帧 `valid=true` 时同步为 `true`。 | 当控制参数 `require_confirmed: true` 时，必须同时为 `true`；当前它与 `valid` 等价。 |
| `error_x` | 相机系横向米制误差，右为正。 | 实际横向伺服控制、对准判定和成功判定。 |
| `error_y` | 相机系纵向米制误差，下为正。 | 实际纵向伺服控制、对准判定和成功判定。 |

控制端处理顺序：

1. 接收一条 `VisionServoTarget`。
2. 若 `valid != true`，立即停止使用该帧的 `error_x/error_y`，进入失目标保护。
3. 若 `require_confirmed == true` 且 `confirmed != true`，保持等待，不执行伺服控制。
4. 只有条件满足时，读取单位为米的 `error_x/error_y` 并进行横向、纵向伺服；阈值也必须以米设置。
5. 连续约 0.2 s 未收到新消息时，按失目标处理，具体超时值由控制周期和现场发布频率确定。

视觉节点每帧均发布该话题：无效帧发送 `valid=false`、`confirmed=false`、`error_x=0.0`、`error_y=0.0`，不得复用上一帧有效误差。有效帧发送米制误差。共享消息中其余字段因兼容工程内其他节点而保留默认值，控制端不得依赖它们。

当前控制端对接注意：控制端现有回调仍会把 `error_x/error_y` 截断为 `[-1,1]`，且保留 `target_id` 过滤。这两个行为来自旧工业相机的归一化误差约定，不适用于本 D435i 米制接口。接入前需要由控制端将订阅话题设为 `/vision/servo/target`，删除该归一化截断，并关闭或移除 `target_id` 匹配；本次未修改控制端源码。
