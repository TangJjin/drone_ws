# 黑线循迹控制端接口说明

## 1. 范围

视觉节点只负责从相机图像中检测黑线，当前不直接发送底盘控制命令。控制端订阅视觉结果，完成安全判断、转向计算和实际执行器命令发布。

当前没有使用地图、单应矩阵、相机标定或米制坐标。所有横向误差都是像素单位。

## 2. 控制端输入接口

| 项目 | 固定值 |
|---|---|
| ROS 2 话题 | `/line_vision/pixel_observation` |
| 消息类型 | `drone_msgs/msg/LinePixelObservation` |
| 发布端 | `drone_perception/line_vision_node` |
| 发布频率 | 由 `observation_fps` 给出，目标为 60 Hz |
| QoS | 默认可靠 QoS，控制端使用 `rclcpp::QoS(10)` 即可 |

查看实时消息：

```bash
ros2 topic echo /line_vision/pixel_observation
```

消息定义：`src/drone_msgs/msg/LinePixelObservation.msg`。

## 3. 控制必须使用的字段

| 字段 | 单位 | 控制用途 | 使用规则 |
|---|---:|---|---|
| `header.stamp` | 时间 | 判断视觉结果是否超时 | 当前时间减去该时间超过阈值时停车 |
| `valid` | 布尔值 | 本帧是否检测到可信黑线 | `false` 时不能使用几何结果 |
| `error_u_px` | 像素 | 横向偏差，作为转向主输入 | 小于 0 为线在左侧；大于 0 为线在右侧 |
| `confidence` | 0 到 1 | 控制许可和速度降级 | 低于阈值时降速或停车 |
| `lost_frame_count` | 帧 | 连续丢线保护 | 超过阈值时停车或进入搜索状态 |
| `line_angle_rad` | 弧度 | 可选的方向前馈 | 只能按“无方向直线”使用，见第 5 节 |

控制端不需要使用以下字段参与第一版转向：

```text
line_center_u_px
line_center_v_px
image_center_u_px
candidate_pixel_count
processing_time_us
capture_fps
observation_fps
decode_ok
roi_valid
```

这些字段用于记录、诊断和故障保护。其中 `decode_ok=false` 或 `roi_valid=false` 时，建议与 `valid=false` 等同处理。

## 4. 建议控制状态机

控制端每次收到消息时缓存最新结果；控制循环固定频率运行，例如 50 Hz。不要在视觉回调中直接阻塞或执行底盘通信。

| 状态 | 进入条件 | 控制输出 |
|---|---|---|
| `STOP` | 启动、视觉超时、`valid=false`、`confidence` 过低或连续丢线过多 | 前进速度 0，转向 0 |
| `TRACK` | `valid=true`，置信度和时间戳均合格 | 根据 `error_u_px` 转向，按规则前进 |
| `DEGRADED` | 有效但置信度较低 | 降低前进速度，继续小幅转向 |
| `SEARCH` | 允许丢线搜索且未达到最终停车条件 | 前进速度 0 或极低，按最后可靠方向慢速搜索；第一版可以不启用 |

第一版建议只使用 `STOP` 和 `TRACK`，避免在丢线时盲目前进。

建议初始安全阈值：

```text
视觉超时：100 ms
最低置信度：0.30
最大连续丢线帧：3
```

这些是初始值，需要按实际底盘速度和制动距离调整。

## 5. 控制计算

### 5.1 横向误差

视觉节点已经计算：

```text
error_u_px = line_center_u_px - image_center_u_px
```

符号固定：

```text
error_u_px < 0：黑线在画面左边
error_u_px > 0：黑线在画面右边
```

控制端先用比例控制即可：

```text
turn_command = clamp(kp_px * error_u_px, -turn_limit, turn_limit)
```

`kp_px` 的正负号必须根据实际底盘转向正方向验证一次。首次低速测试：将黑线移到画面右侧，底盘应朝右修正；若实际向左，令 `kp_px = -kp_px`。

像素误差不是米，不能直接套用位置控制的米制增益。

### 5.2 速度降级

建议根据误差绝对值降速：

```text
abs(error_u_px) <= 40：normal_speed
40 < abs(error_u_px) <= 120：slow_speed
abs(error_u_px) > 120：very_slow_speed
```

如 `valid=false`、消息超时、置信度低于阈值或丢线帧超过阈值，速度必须为 0。

### 5.3 方向角

`line_angle_rad` 来自图像直线拟合，只表示图像中的线方向；直线没有前后方向，因此该角可能相差 `pi`。第一版不要把原始角直接送给航向控制器。

如需要加入方向前馈，控制端必须先按图像竖直方向归一化，并在低速实测确认符号。建议先只用 `error_u_px` 跑通稳定循迹，再加入方向角。

## 6. C++ 控制端订阅示例

```cpp
#include <drone_msgs/msg/line_pixel_observation.hpp>

using Observation = drone_msgs::msg::LinePixelObservation;

auto sub = node->create_subscription<Observation>(
  "/line_vision/pixel_observation", rclcpp::QoS(10),
  [this](const Observation::SharedPtr msg) {
    latest_observation_ = *msg;
    last_observation_time_ = node->now();
  });
```

控制循环的核心逻辑：

```cpp
const bool stale = (node->now() - latest_observation_.header.stamp).seconds() > 0.10;
const bool safe_to_track = latest_observation_.valid &&
  latest_observation_.decode_ok && latest_observation_.roi_valid &&
  latest_observation_.confidence >= 0.30F &&
  latest_observation_.lost_frame_count <= 3U && !stale;

if (!safe_to_track) {
  forward_command = 0.0;
  turn_command = 0.0;
} else {
  turn_command = clamp(kp_px * latest_observation_.error_u_px,
    -turn_limit, turn_limit);
  forward_command = speedFromAbsError(
    std::abs(latest_observation_.error_u_px));
}
```

上面的 `forward_command` 和 `turn_command` 必须由控制端转换为实际底盘使用的接口。当前工作区没有已确认的底盘命令话题，因此不要假定 `/cmd_vel` 已经接入；应在控制端适配器中明确执行器的消息类型、单位、方向和限幅。

## 7. 上电测试顺序

1. 底盘悬空或断开驱动，仅打印控制计算结果。
2. 黑线分别放在画面左、中、右，确认 `error_u_px` 分别为负、接近 0、正。
3. 低速接入转向，确认右侧黑线会让车向右修正；若相反，反转 `kp_px` 符号。
4. 验证丢线、遮挡、相机断流时，控制端在超时阈值内输出 0 速度。
5. 确认后再提高速度，并重新调节像素增益和速度分档阈值。
